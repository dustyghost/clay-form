# UV and image workflow implementation

The unwrap follows the two area-weighted Cauchy–Riemann residuals in [Lévy et al., Least Squares Conformal Maps, SIGGRAPH 2002](https://brunolevy.github.io/papers/LSCM_SIGGRAPH_2002.pdf). Face corners are joined across uncut manifold edges, so a seam creates distinct UV unknowns without changing geometric vertices. Two separated boundary nodes fix the similarity freedom. A matrix-free, Jacobi-preconditioned conjugate-gradient solve minimizes the normal equations; nonconvergence and nonpositive output triangle areas fail before commit. Cancellation is checked during chart construction and iteration.

Chart segmentation and packing are deliberately simpler than the paper's methods: automatic cuts use six dominant face-normal directions, manual mode follows marked seams, and a deterministic shelf packer uses a uniform scale with explicit padding. Closed/nonmanifold charts and folded results need more seams. There is no claim that every input produces an injective parameterization; the editor separately checks overlap and reports its bounded-work limit. The generated cylinder, cube and sphere fixtures cover the intended initial workflows.

`Mesh::uv` stores triangle-corner coordinates and the topology they belong to. A topology mismatch disables rendering and painting through the old mapping. New saves use version 3 to prevent older applications silently discarding UVs or images. Images have stable IDs, copy-on-write RGBA16 integer or RGBA32 float pixels, explicit channel interpretation and optional external-exchange metadata. Three 4K images (or equivalent smaller images) bound the scene's image storage. Lossless packed words are uploaded through 1024² texture-array pages, avoiding storage-buffer binding limits while preserving 32-bit float values. History counts shared pixel allocations once and defaults to a 1024 MiB ceiling. Native pixels are losslessly compressed with a precision tag; project files are capped at 2 GiB. Diagnostic exports remove external exchange paths.

The GPU receives per-corner UVs independently of smoothing fans and per-model texture descriptors into deduplicated pixel pages. Bilinear filtering operates on premultiplied linear samples. Paint rasterizes UV triangles, interpolates masks and surface positions, and evaluates the brush in 3D. Projected triangle bins accelerate exact frontmost-surface checks. A stroke uses the existing transactional paint history and propagates images to shared IDs. Four-pixel gutter dilation never crosses occupied UV texels.

GIMP integration uses an executable plus one literal file argument, without a shell. A fingerprint of the exported pixels/dimensions detects concurrent local changes. Decode, profile conversion and validation finish before replacing the current image. The pinned `moxcms` library, already present transitively through `image`, performs RGB ICC conversion. Linear data images bypass it. OpenEXR half/full float RGB(A) imports retain 32-bit float samples; exports write full float. Colour EXRs use linear Rec.709 and associated alpha on disk; data channels bypass colour conversion and share the associated-alpha convention. Non-Rec.709 colour primaries are rejected explicitly. The OpenEXR channel and colour conventions follow the [official technical introduction](https://openexr.com/en/latest/TechnicalIntroduction.html). The manual GIMP fixture is separate from routine CI.

GIMP 3.2 EXR exchange has a dedicated alpha adaptation: its native loader reads straight RGB, while its GEGL exporter writes associated RGB. **Edit in GIMP** therefore sends straight RGB and Reload reads the standard associated result. Ordinary **Export image** writes standard associated EXR. The behaviour is verified against GIMP 3.2.6 and the [GEGL EXR exporter](https://github.com/GNOME/gegl/blob/master/operations/external/exr-save.cc). The reproducible GIMP fixture checks negative/HDR values and nonopaque alpha across this path.

## Layered Photoshop exchange

The native PSD writer follows [Adobe's Photoshop File Formats Specification](https://www.adobe.com/devnet-apps/photoshop/fileformatashtml/): RGB headers, planar layer channels, ZIP channel compression, normal blending, layer protection, active-layer state and ICC resources. It emits two ordinary raster layers at the source texture's 16-bit integer or 32-bit float precision. The UV guide uses a reserved layer name so different paint applications can preserve its identity without a GIMP-specific attachment.

Reload uses the installed GIMP 3 Python compositor on a disposable document. It excludes the guide by its reserved name (including inside groups), composites visible paint and leaves the PSD unchanged. Native Photoshop validation remains unavailable. The installed GIMP 3.2.6 reads the generated float PSDs but exports PSD at 16-bit; float downgrade is therefore checked and rejected during Reload.
