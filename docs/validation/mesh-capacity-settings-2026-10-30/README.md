# Configurable mesh capacity

Under #103, following the [deformation scan work](../deformation-scan-2026-10-30/README.md).

## Behavior

**Settings → Mesh capacity** persists independent vertex and triangle limits in application preferences. Defaults remain 500,000 vertices / 1,000,000 triangles per mesh. Allowed maxima are 16,000,000 vertices / 32,000,000 triangles. These are configurable budgets, not demonstrated performance capacities.

Changes apply after restart. The panel shows both the saved values and the active session values, provides a reset control and identifies pending changes. Ordinary shortcut handling, sculpting, temporary masking and direct edit commands are blocked while the dialog is open.

Validated preferences initialize a process-wide immutable budget before recovery and mesh workers start. All threads use that same budget for the lifetime of the process. Existing preferences without the new field receive the original defaults. Workspace layouts do not change capacity, and projects do not override the user's budget.

The shared counts replace the previous constants in mesh/UV/crease validation, subdivision and stack budgets, adaptive triangle/quad refinement, remeshing, merge, mirror, slice, thickness and modeling/edge growth. The optimized-quad subdivision scratch guard scales with the same budget. OBJ count checks and errors use the active limits. Above-budget mesh/project validation tells the user to adjust Settings and restart.

File byte limits, texture limits, maximum subdivision levels and algorithm work budgets remain separate. Lowering the configured limits does not simplify existing geometry. A project above the active limits requires raising them again before loading. No user's installed preferences were changed during development.

## Reproduce

```sh
cargo test --locked --lib mesh_capacity -- --nocapture --test-threads=1
cargo test --locked --lib buttons_shortcuts_and_direct_edits_share_modal_and_job_policy -- --test-threads=1
cargo test --locked --lib gpu_mesh_capacity_settings_capture -- --ignored --nocapture --test-threads=1
```

The capture defaults to `/tmp/clay-mesh-capacity.png`; `CLAY_MESH_CAPACITY_PREVIEW` overrides its output path. See [Change mesh capacity](../../guide/workspace.md#change-mesh-capacity) for user instructions.
